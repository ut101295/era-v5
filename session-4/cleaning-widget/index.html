01 How many strategies — and what they are

The session lays out data cleaning as an ordered pipeline, not a menu. Counting the transforms the closing commitments name explicitly gives the headline answer: 8 cleaning strategies. With honest nuance it is a 10-stage pipeline (add extraction, carried over from Session 3, and split deduplication into its local mechanism and global scale halves — each gets its own section and widget), plus 2 operational artifacts from the Minor (a collection tracker and a central dedup machine).

The count I defend: 8. normalization · format discipline · quality filtering · deduplication · language validation · PII removal · decontamination · manifest/provenance. Below, each is described and then run for real on the Assamese corpus.

02 The dataset I picked

Primary corpus

Why this one (and not the reasoning-distilled example)

  • It's from the Session 3 research family. Session 3 anchored Indic pre-training on the AI4Bharat corpora (Sangraha, IndicCorp v2); this is IndicCorp v2.
  • It exercises the sovereign thread end-to-end — Brahmic joiners in normalization, script-aware quality rules, the Assamese/Bengali language-ID trap, and Indic PII false-positives — which a clean English set never would.
  • Two small secondaries fill the gaps: 300 Bengali docs mislabeled as Assamese (to give language-ID a real mismatch to catch) and 2,000 real Indic instruction pairs (to demonstrate the ghost-tag / format stage).

05 Other strategies & concerns cleaned up

The Minor — operational artifacts

Live cleaning-numbers tracker

Deduplication and collection are a shared, measured effort, not a private task. A tracker shows who has shipped how many clean tokens and which language pools are still under-served, so effort moves toward the gaps. This run contributes clean Assamese tokens to that ledger.

The central dedup machine

Duplication is global: two students can each dedup their own shard perfectly and still leave a doc that appears in both. In this run, of the near-duplicates were cross-shard — invisible to any local pass. That is why the course provisions one large-memory, checkpoint-resumable, single-owner machine to run the one global pass everything depends on.

Extra defects our own run caught (the honest gallery)

Filter bias, quantified. An English-tuned quality filter would have dropped of the good Assamese documents this pipeline kept — a near-total wipe of the low-resource corpus. Filtering is not a neutral step; it is a decision about which languages the model will be able to speak.

07 Manifest & reproducibility

A clean corpus is only trustworthy if we can say exactly where it came from and reproduce it. The content hash is computed after cleaning; identifiers are content-addressed, not running counters; an unknown or unsafe license blocks the shard. The same input gives the same hash on every run.
